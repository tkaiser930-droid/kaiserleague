KAISER FAMILY FANTASY SMX — GITHUB + RENDER LEAGUE-DATA SYNC

PURPOSE
- Render's persistent disk remains the live working database at /var/data/league-data.json.
- GitHub stores a second copy of that same JSON file, by default at league-data/league-data.json in the configured repository.
- On server startup, the server checks both files and loads whichever has the newer savedAt timestamp.
- Whenever the live JSON file changes through the website or a direct file edit, the server automatically commits the updated JSON to GitHub after a short debounce.
- The GitHub copy is a backup of league data, not a backup of website source code.

GITHUB SETUP
1) The configured repository is tkaiser930-droid/LeagueSave. The service automatically detects that repository's default branch unless GITHUB_BRANCH is explicitly set.
2) Create a fine-grained personal access token restricted to that repository.
3) Grant Contents: Read and write, and Metadata: Read.
4) Set these values in Render > Service > Environment:
   - GITHUB_TOKEN = your fine-grained token
   - GITHUB_REPOSITORY = tkaiser930-droid/LeagueSave
   - GITHUB_BRANCH = (leave blank to auto-detect the repository default branch)
   - GITHUB_DATA_PATH = league-data/league-data.json
   - GITHUB_BACKUP_PASSWORD = a separate long password for the manual Save/Sync buttons
   - GITHUB_AUTO_BACKUP = true
5) If GITHUB_REPOSITORY was previously set to a different name, edit the existing Render variable and change it to exactly tkaiser930-droid/LeagueSave. Save and restart/redeploy the service.

LOCAL DEVELOPMENT
1) Copy .env.example to .env.
2) Fill in the same variables.
3) Run npm start.

HOW SAVING WORKS
- Startup scan: the server reads Render/local league-data.json and the GitHub JSON copy. It compares savedAt timestamps. If GitHub is newer, it loads GitHub into the live data directory. If Render/local is newer (or GitHub has no file), it keeps the live file and updates GitHub when automatic backup is enabled. Render wins exact timestamp ties.
- Automatic GitHub save: a change to league-data.json through the app is written to Render/local storage first, then the updated JSON is committed to GitHub. A file watcher also catches direct edits to the JSON file.
- Manual Render/local save: use Save / Flush to Render or Local Server on the Data & Backup page.
- Manual GitHub save: enter GITHUB_BACKUP_PASSWORD and use Save Current League JSON to GitHub.
- Manual comparison: enter GITHUB_BACKUP_PASSWORD and use Scan GitHub & Render — Load Newest Save. The selected save is loaded and the page reloads.
- Manual portable backup: Download League Backup and Restore a Backup (.json) remain available and unchanged.

TROUBLESHOOTING
- The Data & Backup status must show repository tkaiser930-droid/LeagueSave. If it shows a different repository, the Render Environment variable GITHUB_REPOSITORY is overriding the default; correct that variable and redeploy.
- If status reports 401, create a valid token. If it reports 403, grant Contents: Read and write and Metadata: Read to this exact repository. If it reports 404, verify the repository spelling and that the token has access to it.
- If the repository has no commits yet, the first backup now initializes the first tree, commit, and default branch. No README or starter file is required.
- If the first backup has succeeded, the status should show a GitHub JSON save timestamp and the commit link/SHA.

IMPORTANT
- GITHUB_TOKEN is only read by the Node server from environment variables or an untracked .env file. Never put it in app.js, HTML, browser storage, or a committed file.
- Do not remove the Render persistent disk. It remains the live database location.
- GitHub save path is controlled by GITHUB_DATA_PATH and defaults to league-data/league-data.json. The repository is preconfigured as tkaiser930-droid/LeagueSave. The service detects the repository's default branch; set GITHUB_BRANCH only if you intentionally want a different branch.
- If the repository has no commits/branch yet, the first automatic save creates the initial Git tree, commit, and branch. This avoids the common empty-repository failure from the Contents API.
- If GitHub cannot be reached during startup, the server keeps the Render/local file and logs the error rather than replacing live data with an empty save.

SEASON HISTORY NOTE
The historical-season archive is stored inside the same complete `league-data.json` database under the protected `kaiserFantasyHistoricalSeasons` key. It is intentionally omitted from the public `/api/state` endpoint but is included in the full GitHub JSON mirror and commissioner backup exports. Keep the configured GitHub repository private so archived rider, team, scoring and event history remains commissioner-only.
