Score Race Results

Choose a series, division, and scheduled event. SMX scoring changes by event type, and Supercross events offer Standard or Triple Crown bonus formats. Motocross and Triple Crown Series use separate Moto 1 and Moto 2 tabs with 40 positions each. MXGP has Qualifying Race, Moto 1, and Moto 2 tabs; its Moto 1 and Moto 2 scoring includes fastest lap only. MXGP Qualifying Race awards 10–1 points for 1st–10th and 0 points for 11th–40th. MXON has six tabs: MX2 Qualifying Race, MXGP Qualifying Race, Open Qualifying Race, Moto 1, Moto 2, and Moto 3. MXON qualifying tabs award 10–1 points for 1st–10th and 0 points for 11th–40th; MXON moto tabs use MXGP moto finish points. All six tabs filter athletes by their MXON secondary-series affiliations. F1 Sprint events use Grand Prix and Sprint tabs; MotoGP always has both tabs. Free agents can be selected for bonus awards. Athletes already scored for the same event, round, division, and scoring segment are removed from the selection list. Riders can still be entered separately for another moto, sprint, or qualifying segment.

SMX scoring: 20 rider slots. All scoring points, including bonuses, are multiplied for Round 2 and Round 3.

Import Official Race Results

SMX uses the official SuperMotocross archive and enforces the selected 250 / 450 class and session. Triple Crown Series matches the scheduled event and uses its Full Event Results Moto 1 / Moto 2 columns for the selected CAN 250 / CAN 450 class. MXGP automatically selects the official Infront Championship, Class, Grand Prix round and Session filters from the Commissioner selections. MXON uses its selected official classification URL. MotoGP uses its official results archive to match the scheduled season / event and fetch the selected Grand Prix Race or Sprint session plus Qualifying 2 for the fastest-qualifier bonus. F1 uses its official season archive, keeps NC drivers in official displayed order, and fetches Qualifying / Sprint Qualifying and Grand Prix Fastest Laps. All results are previewed before they are loaded into the scoring table.

SMX: use the official SuperMotocross results archive or a direct 250 / 450 session result link. The selected class is enforced before results load. For CSV uploads, include Position and Rider (or Driver); Number, Team, Best Lap and Class are optional.

Loading positions does not submit scores. Review the rider matches, finishing places and bonus checkboxes in the scoring table before recording results.

Checking GitHub league save…

The latest timestamps will appear here.

GitHub is the sole shared server-side database. The website server holds only an in-memory copy while running. Download League Backup and Restore a Backup remain available for local/offline copies. The GitHub token is stored only in server environment variables.

GitHub league-data setup instructions
  1. The backup repository is preconfigured as tkaiser930-droid/LeagueSave. Its default branch is detected automatically. Set GITHUB_BRANCH only if you intentionally want to use a different branch.
  2. Create a fine-grained personal access token restricted to that repository with Contents: Read and write and Metadata: Read.
  3. On Render, set GITHUB_TOKEN and GITHUB_BACKUP_PASSWORD in the service Environment page. Confirm GITHUB_REPOSITORY=tkaiser930-droid/LeagueSave.
  4. Leave GITHUB_BRANCH blank for automatic default-branch detection. Set GITHUB_SEASON_DIRECTORY=league-data/seasons, GITHUB_SEASON_INDEX_PATH=league-data/season-index.json, and KF_ACTIVE_SEASON=2027. GITHUB_DATA_PATH=league-data/league-data.json is used only to migrate an older single-file save when the 2027 season file does not exist.
  5. Restart/redeploy the Node service. On startup it loads the active year from GitHub. Every subsequent league change is committed to that year's separate JSON file before the save request is reported successful.

Locally, copy .env.example to .env and enter the same values. Never put your GitHub token in browser code or commit it to the repository.

Local save download

Download a portable JSON copy of the current league. This local save download is independent of GitHub and can be kept on your computer as an extra backup.

Restore a local backup

Choose a JSON backup previously downloaded from this page. Restoring replaces the currently selected season only; other years remain in their separate GitHub files.

Important

For shared saving, run the Node service with GITHUB_TOKEN configured and use the included GitHub repository settings. The Render web service does not need a persistent disk. If GitHub is unavailable or you open the site with VS Code Live Server, the banner will say “Browser-only storage”; changes remain in that browser until GitHub reconnects or you download a JSON backup.

Before removing the old persistent disk from a deployment that previously used it, first save the current live league JSON to GitHub from this page and download a local JSON backup. Confirm that the GitHub save is present before detaching the disk.

If your terminal reports that port 10000 is already in use, stop the other Node server first, then run npm start again.

Yearly Reset

Prepare for a new fantasy season by clearing every team roster, resetting all accumulated team and athlete points, and deleting all trade proposals and their notification history. This permanently deletes scoring records, including athlete profile results, averages, scoring history, and top-undrafted scoring totals. Athlete records, team names, owners and passwords, draft settings, and the event schedule remain unchanged.
