Score Race Results

Choose a series, division, and scheduled event. SMX scoring changes by event type, and Supercross events offer Standard or Triple Crown bonus formats. Motocross and Triple Crown Series use separate Moto 1 and Moto 2 tabs with 40 positions each. MXGP has Qualifying Race, Moto 1, and Moto 2 tabs; its Moto 1 and Moto 2 scoring includes fastest lap only. MXGP Qualifying Race awards 10–1 points for 1st–10th and 0 points for 11th–40th. MXON has six tabs: MX2 Qualifying Race, MXGP Qualifying Race, Open Qualifying Race, Moto 1, Moto 2, and Moto 3. MXON qualifying tabs award 10–1 points for 1st–10th and 0 points for 11th–40th; MXON moto tabs use MXGP moto finish points. All six tabs filter athletes by their MXON secondary-series affiliations. F1 Sprint events use Grand Prix and Sprint tabs; MotoGP always has both tabs. Free agents can be selected for bonus awards. Athletes already scored for the same event, round, division, and scoring segment are removed from the selection list. Riders can still be entered separately for another moto, sprint, or qualifying segment.

SMX scoring: 20 rider slots. All scoring points, including bonuses, are multiplied for Round 2 and Round 3.

COMMISSIONER TOOL

Import Official Race Results

SMX uses the official SuperMotocross archive and enforces the selected 250 / 450 class and session. Triple Crown Series matches the scheduled event and uses its Full Event Results Moto 1 / Moto 2 columns for the selected CAN 250 / CAN 450 class. MXGP automatically selects the official Infront Championship, Class, Grand Prix round and Session filters from the Commissioner selections. MXON uses its selected official classification URL. MotoGP uses its official results archive to match the scheduled season / event and fetch the selected Grand Prix Race or Sprint session plus Qualifying 2 for the fastest-qualifier bonus. F1 uses its official season archive, keeps NC drivers in official displayed order, and fetches Qualifying / Sprint Qualifying and Grand Prix Fastest Laps. All results are previewed before they are loaded into the scoring table.

LEAGUE STORAGE

Data & Backup

Where your league saves

Checking the active storage mode…

With local development, current-season riders, teams, scores, trades, draft picks, settings, schedules, and protected historical seasons are stored in data/league-data.json. On Render, the same database file is stored on the attached persistent disk at /var/data/league-data.json. Historical seasons remain in this same save file but are available only through the commissioner-authenticated API.

SECONDARY LEAGUE-DATA BACKUP

GitHub + Render Save Sync

The server checks the live Render JSON file (/var/data/league-data.json) against the GitHub copy in tkaiser930-droid/LeagueSave when it starts. It loads whichever save has the newer savedAt timestamp. When the live league JSON changes, the server automatically commits that updated JSON file to GitHub after the write settles. A brand-new, empty GitHub repository is initialized automatically on the first save.

Checking Render and GitHub saves…

The latest timestamps will appear here.

Render remains the live working database and continues saving to its persistent disk. GitHub is a timestamp-compared mirror of the same JSON save. Manual JSON download/import and the Render/local Save / Flush option below remain available. The GitHub token is stored only in server environment variables.

GitHub league-data setup instructions
  1. The backup repository is preconfigured as tkaiser930-droid/LeagueSave. Its default branch is detected automatically. Set GITHUB_BRANCH only if you intentionally want to use a different branch.
  2. Create a fine-grained personal access token restricted to that repository with Contents: Read and write and Metadata: Read.
  3. On Render, set COMMISSIONER_PASSWORD, GITHUB_TOKEN and GITHUB_BACKUP_PASSWORD in the service Environment page. Confirm GITHUB_REPOSITORY=tkaiser930-droid/LeagueSave.
  4. Leave GITHUB_BRANCH blank for automatic default-branch detection. Keep GITHUB_DATA_PATH=league-data/league-data.json and GITHUB_AUTO_BACKUP=true.
  5. Restart/redeploy the Node service. On startup it compares the saved timestamps and selects the newest copy. Later changes to league-data.json are committed to GitHub automatically.

Set COMMISSIONER_PASSWORD, GITHUB_TOKEN and the other values in the Node.js process environment before starting the server. Never put a real password or GitHub token in browser code or commit it to the repository.

Export a backup

Download a JSON backup of the saved league. When signed in as Commissioner, the backup also includes private historical seasons. Keep a backup before replacing project files, importing old data, archiving a year, or resetting the league.

Restore a backup

Choose a backup JSON file previously downloaded from this page. Restoring replaces the current league data, so export a backup first if you need to keep the current version.

Important

Run locally with npm start for project-file saving. On Render, configure the service using the included render.yaml and keep the persistent disk mounted at /var/data. If you open the site with VS Code Live Server, the banner will say “Browser-only storage”; changes then stay in that browser's storage until exported. Render data persists across deploys only when a persistent disk is attached.

If your terminal reports that port 5500 is already in use, stop Live Server in VS Code first, then run npm start again.
