LEAGUE STORAGE

Data & Backup

Where your league saves

Checking the active storage mode…

With local development, riders, teams, scores, trades, draft picks, settings, and schedule events are stored in data/league-data.json. On Render, the same database file is stored on the attached persistent disk at /var/data/league-data.json. The database file is not served directly to the browser.

SECONDARY LEAGUE-DATA BACKUP

GitHub + Render Save Sync

The server checks the live Render JSON file (/var/data/league-data.json) against the GitHub copy in tkaiser930-droid/LeagueSave when it starts. It loads whichever save has the newer savedAt timestamp. When the live league JSON changes, the server automatically commits that updated JSON file to GitHub after the write settles. A brand-new, empty GitHub repository is initialized automatically on the first save.

Checking Render and GitHub saves…

The latest timestamps will appear here.

Render remains the live working database and continues saving to its persistent disk. GitHub is a timestamp-compared mirror of the same JSON save. Manual JSON download/import and the Render/local Save / Flush option below remain available. The GitHub token is stored only in server environment variables.

GitHub league-data setup instructions
  1. The backup repository is preconfigured as tkaiser930-droid/LeagueSave. Its default branch is detected automatically. Set GITHUB_BRANCH only if you intentionally want to use a different branch.
  2. Create a fine-grained personal access token restricted to that repository with Contents: Read and write and Metadata: Read.
  3. On Render, set GITHUB_TOKEN and GITHUB_BACKUP_PASSWORD in the service Environment page. Confirm GITHUB_REPOSITORY=tkaiser930-droid/LeagueSave.
  4. Leave GITHUB_BRANCH blank for automatic default-branch detection. Keep GITHUB_DATA_PATH=league-data/league-data.json and GITHUB_AUTO_BACKUP=true.
  5. Restart/redeploy the Node service. On startup it compares the saved timestamps and selects the newest copy. Later changes to league-data.json are committed to GitHub automatically.

Locally, copy .env.example to .env and enter the same values. Never put your GitHub token in browser code or commit it to the repository.

Export a backup

Download a JSON backup of the saved league. Keep a backup before replacing project files, importing old data, or resetting the league.

Restore a backup

Choose a backup JSON file previously downloaded from this page. Restoring replaces the current league data, so export a backup first if you need to keep the current version.

Important

Run locally with npm start for project-file saving. On Render, configure the service using the included render.yaml and keep the persistent disk mounted at /var/data. If you open the site with VS Code Live Server, the banner will say “Browser-only storage”; changes then stay in that browser's storage until exported. Render data persists across deploys only when a persistent disk is attached.

If your terminal reports that port 5500 is already in use, stop Live Server in VS Code first, then run npm start again.
